# Mobile transcript performance

The change reduced JavaScript stalls in a fixed native transcript workload.
The primary result is a 70.8% reduction in the median p95 JavaScript frame interval.

| Production JavaScript measurement | Baseline | Optimized | Change |
| --- | ---: | ---: | ---: |
| Median p95 JS frame interval | 92.06 ms | 26.93 ms | 70.8% lower |
| Median p50 JS frame interval | 81.50 ms | 16.70 ms | 79.5% lower |
| Timer updates served per second | 11.99 | 16.07 | 34.0% higher |

These are medians across three trials per version, with mobile/bun.lock installed.
The baseline p95 values were 87.14, 92.06, 97.01 ms.
The optimized values were 26.32, 26.93, 28.06 ms.

## Implementation

- Memoize completed reply bodies so unchanged Markdown does not render on every draft update.
- Use React Native unstable_VirtualView inside assistant reply bodies. Distant bodies can unmount while native measured placeholders retain their geometry.
- Keep TranscriptRow, its entrance animation, user-message expansion, and tool sheets outside the virtualized body. This avoids the state-loss boundary in the source-session draft.
- Use startTransition for transcript message and draft updates. Keep input state outside those transitions.
- Fall back to ordinary memoized Markdown on web and clients without the native component.

The benchmark measures these changes together. It does not isolate the contribution
of VirtualView from memoization or transition scheduling.

## Method

Date: 2026-09-13. Worktree base: eb8ecacbde28a07d5f088006b3d42e4d2c4ceb71.

Device: iPhone 17 simulator, iOS 26.0, UDID 84C3046E-1FDF-48C7-9751-6C245C2D9620.
The simulator ran on the paired Mac. The native omg development client loaded
both variants from the same Metro server. Native VirtualView availability was
true in all six final trials.

Installed JavaScript stack: Expo 57.0.12, React Native 0.86.2, React 19.2.3,
Reanimated 4.5.1. No dependency changes are part of the patch.

The standalone benchmark imports the product TranscriptRow and Markdown components.
It renders 40 fixed rows: 36 Markdown replies and four long user messages.
Each trial has a five-second warmup, four native linear scroll legs over 16 seconds,
and a 50 ms timer that updates a streaming tail. The scroll extent was identical
in every trial: 23758.33 points. The order is baseline, optimized, optimized,
baseline, baseline, optimized. Each trial mounts a fresh list.

Six final production-JavaScript trials were recorded after a frozen Bun install.
The primary table uses these results: Metro --no-dev --minify, with dev:false in
every result. 2026-09-13-environment.json records exact versions and source hashes.

An earlier npm install selected Expo 57.0.22. Six development and six production
trials from that exploratory run are retained separately in
2026-09-13-exploratory.jsonl. They are not mixed into the primary table. In that
exploratory development run, median React Profiler render time fell from
10077.1 ms to 7031.8 ms per trial (30.2%), while more updates were served.
Profiler durations are unavailable in the production React build.

## Limits

- This is a local fixture benchmark using real native transcript components. It does not time authenticated session loading, server processing, or the full network-to-screen path.
- The native binary is a development client. The JavaScript is minified with development checks disabled. This is not an App Store build or a physical-device result.
- JS requestAnimationFrame intervals measure JavaScript responsiveness. They are not display FPS or touch-to-paint latency.
- The Reanimated native callback intervals covered only 72–81% of wall time in the production trials. They do not support an FPS claim. Raw values remain in the data, including the optimized variant's longer callback intervals.
- Timer updates served are a measure of callback throughput under load, not network throughput. A blocked JS thread serves fewer timer callbacks.
- No memory, battery, startup, Android, or 120 Hz gain is established.

## Verification

The mobile type check passes. Focused rendered tests pass in native, web-fallback,
and older-client modes. The tests cover memoization, hidden-body restoration,
surrounding row lifetime, baseline behavior, and fallback rendering.

On the iPhone 17 simulator, the expanded user message stayed expanded after a
Top-to-Bottom-to-Top scroll. The tool sheet opened and dismissed correctly.
At 75% list width, reply text reflowed and the table retained its horizontal
scroll surface. Screenshots were captured for these checks.
